# Plan — `webtyp.com/model`: one list item, declared once, built by generated code

## Why

v0.2.7 added `Field.Row`, `model.Row{ID, Title, Detail, Badge}` and `model.RowOf`, which walks the schema, boxes
every value and converts it to text **at runtime**. Three defects came with it:

1. **Two types for one idea.** `model.Row` and `view.Item{ID, Label, Description, Badge}` hold the same four slots
   under different names, plus a translator (`view.itemOf`). The field mark speaks a third vocabulary (`RowTitle`).
2. **Cost.** `view` calls `RowOf` just to read an id, inside loops (`view/records.go:37,40,59,70`,
   `view/presenter.go:56,85`): O(N²) projections per list, re-run on every filter keystroke — heavy in TinyGo WASM.
3. **Nothing typed.** The field → text link is a runtime walk; a typo or a model without marks fails late.

From now on there is **one** type, `model.Item` (the name the whole ecosystem already uses: `Items()`,
`SetItems`, `targetlist.Item`), the field mark speaks its vocabulary (`Item: model.ItemLabel`), and `ormc`
generates a typed `func (m *X) Item() model.Item` that reads the fields directly. Adding a field to the list is one
line on that field. Breaking change, no compatibility layer.

- Precedents for generated, typed projection: sqlc and protoc generate typed code instead of a runtime walk.

## Design gate

1. **Prior art.** Django `__str__` + `list_display`, Rails `to_s` + ActiveAdmin columns (one projection per model,
   declared once); sqlc/protoc (typed generated code over a runtime walk); Apollo/Ember Data (compute on write).
2. **Novice-name test.** `{Name: "name", …, Item: model.ItemLabel}` — «in the item, this is the label»; the mark
   names the field of `model.Item` it fills (`ItemLabel` → `Item.Label`). `rec.Item()` — «the item of this record».
3. **Complexity ledger.** Concepts −3 (`Row`, `RowOf`, `RowSlot`) +2 (`Item`, `ItemSlot`) +1 (`JoinItem`); vocabularies
   for one idea 3 → 1; runtime work per list O(N²) projections → N generated calls.
4. **Where it belongs.** The item is a fact about the record (`model`); `ormc` writes it; `view` only reads it.
5. **What it deletes.** `Row`, `RowSlot`, `RowNone/RowTitle/RowDetail/RowBadge`, `RowOf`, `ValidateRow`,
   `rowDetailSeparator`, `Field.Row`.

## Stage 1 — `item.go` (replaces `row.go`; delete `row.go`)

```go
package model

import "webtyp.com/fmt"

// Item is ONE record shown as an entry of a list — the neutral form any renderer
// draws. ormc generates func (m *X) Item() Item from the fields marked Item:…;
// never write it by hand.
type Item struct {
	ID          string // the primary key, as text: the selection key
	Label       string // primary text (the field marked ItemLabel)
	Description string // secondary text (the fields marked ItemDescription, joined with JoinItem)
	Badge       string // leading badge (the field marked ItemBadge); a date/time field is seconds since 1970, as text
}

// Itemizer is a record that can be shown as a list entry. ormc implements it.
type Itemizer interface {
	Item() Item
}

// ItemSlot is the field of Item a model field fills. The zero value keeps it out.
type ItemSlot uint8

const (
	ItemNone        ItemSlot = iota // not shown in the list
	ItemLabel                       // Item.Label; exactly one per listed model
	ItemDescription                 // Item.Description; several are joined with JoinItem, in field order
	ItemBadge                       // Item.Badge; at most one
)

// itemSeparator joins several ItemDescription values.
const itemSeparator = " · "

// JoinItem joins the non-empty parts with " · ". Generated Item() methods call it
// when several fields are marked ItemDescription.
// Example: model.JoinItem("local", "", "Oficina") == "local · Oficina"
func JoinItem(parts ...string) string {
	out := ""
	for _, p := range parts {
		if p == "" {
			continue
		}
		if out != "" {
			out += itemSeparator
		}
		out += p
	}
	return out
}

const (
	errItemTwoLabels  = "model: two fields marked ItemLabel: "
	errItemTwoBadges  = "model: two fields marked ItemBadge: "
	errItemNoLabel    = "model: fields marked ItemDescription or ItemBadge need a field marked ItemLabel"
	errItemNoPK       = "model: a listed model needs a primary key field"
	errRefAndOptions  = "model: a field cannot have both Ref and Options: "
)

// ValidateItem reports the first rule the fields break: at most one ItemLabel and
// one ItemBadge, an ItemLabel and a primary key whenever any field is marked, never
// Ref and Options on the same field. ormc calls it when it generates.
// Example: if err := model.ValidateItem(ServiceModel.Fields); err != nil { … }
func ValidateItem(fields []Field) error {
	label, badge, marked, pk := "", "", false, false
	for _, f := range fields {
		if f.Ref != nil && f.Options != nil {
			return fmt.Err(errRefAndOptions + f.Name)
		}
		if f.IsPK() {
			pk = true
		}
		switch f.Item {
		case ItemLabel:
			if label != "" {
				return fmt.Err(errItemTwoLabels + label + ", " + f.Name)
			}
			label = f.Name
			marked = true
		case ItemBadge:
			if badge != "" {
				return fmt.Err(errItemTwoBadges + badge + ", " + f.Name)
			}
			badge = f.Name
			marked = true
		case ItemDescription:
			marked = true
		}
	}
	if marked && label == "" {
		return fmt.Err(errItemNoLabel)
	}
	if marked && !pk {
		return fmt.Err(errItemNoPK)
	}
	return nil
}
```
